# M2 MVE-0 — SmolVLA on the 6 GB laptop GPU (2026-11-26)

Status: **MVE-0 pass, L1 offline GPU** (no robot, no DDS, no motion).
This is a feasibility probe for M2, not a training result and not an
acceptance of a policy.

## 1. Question

Can `lerobot/smolvla_base` (450M parameters, 100M learnable with the default
SmolVLA presets) complete a fine-tuning optimizer step on the 6 GB RTX 3060
Laptop, and how much batch headroom is available?

## 2. Setup

| Item | Value |
|---|---|
| GPU | NVIDIA GeForce RTX 3060 Laptop GPU, 6144 MiB (5.67 GiB usable; 112 MB held by another process) |
| Driver / CUDA | 595.99.02 / CUDA 13.2 |
| Python | 3.12.3 |
| torch | 2.15.0+cu132 |
| lerobot | 0.7.0 |
| transformers | 5.22.2 |
| Model | `lerobot/smolvla_base`, Apache-2.0 |
| Dataset | deterministic synthetic ArmPi Ultra: 1 episode, 60 frames, 10 fps, 64×48, 2 cameras |
| Policy input | `empty_cameras=1`; `external→camera1`, `wrist→camera2` |
| Training | 1 optimizer step per batch, `num_workers=0`, no evaluation |

The dataset was generated by `jcheng-dataset synth` and exported with
`jcheng-dataset convert --mode images`; the policy-side resize/padding to
512×512 is unchanged by the small source image.

## 3. Results

| Batch | Result | Step time | Peak allocated VRAM | Loss |
|---:|---|---:|---:|---:|
| 1 | pass | 1.449 s | 1.67 GB | 1.400 |
| 2 | pass | 0.958 s | 1.67 GB | 2.016 |
| 4 | pass | 1.161 s | 2.01 GB | 3.643 |
| 8 | pass | 1.391 s | 3.14 GB | 3.942 |
| 16 | OOM | — | 5.19 GB allocated before failure | — |
| 32 | OOM | — | 5.22 GB allocated before failure | — |

Conclusion: **batch 8 fits with roughly 2.5 GB of headroom; batch 16 does not.**
M2 should start with batch 8 (or a smaller batch plus gradient accumulation)
and treat the exact 8–16 boundary as unmeasured.

## 4. Limitations

- One step per batch says nothing about convergence, loss curves or success
  rate.
- The source images are 64×48; the policy resizes/pads to 512×512. Real
  640×480 decode/load cost is not measured here.
- The OOM runs include a 112 MB unrelated GPU process and allocator
  fragmentation; the boundary was not bisected.
- The step-1 checkpoint under `/tmp` was disposable and is not promoted.
- No robot, camera, DDS, lease, `ExecuteMotion` or motion path was touched.
